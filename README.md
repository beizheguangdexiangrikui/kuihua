## 这是什么

它不是又一个套壳聊天框，而是把「模型接入 → 提示词编排 → 工具调用 → 结果验证」做成一条完整流水线：

- **多模型直连**：DeepSeek / OpenAI / Claude / Gemini / 通义 / Kimi / 智谱 / 硅基流动 / OpenRouter / 小米 MiMo 等 27 家，一个界面切换
- **提示词模板引擎**：8 份内置模板，一键作为 system 注入，可编辑、可还原、可导入导出
- **本地工具箱**：阅读、写入、编辑、预览、终端、目录、截图、联网搜索、抓网页——模型不只会说，还能动手
- **插件生态**：321 个插件入口，MCP 服务器一键安装/启用/卸载，装完即可被模型调用
- **指令遵循度检测**：五探针自动测试模板生效情况，输出百分比、评级与范围明细
- **拒答自动换路**：被拒答时自动换代际 / 换网关 / 加强预填，不再一条路撞死
- **防封中心**：Claude 与 GPT 分别体检，出口线路、环境一致性、请求节奏、地区跳变一次查清
- **省 token 模式**：长会话只发最近若干条、模板只注入一次，帮你在长对话里省钱
- **桌面体验**：系统托盘、黑白主题、美化皮肤、实时 API 余额、拖拽附件、应用内更新

### 5. 指令遵循度检测（五探针）

| 探针 | 测什么 |
|---|---|
| 口令回执 | 模板里写死了自检口令。回了口令 = 模型**真的在执行这份人格**。最能一眼看出模板有没有真的生效 |
| 拒绝话术 | 会不会出现「我不能 / 作为AI / 建议你咨询专业人士」这类句式 |
| 说教与免责 | 会不会自己加免责声明、风险提示 |
| 第一行直接给内容 | 开头是「好的 / 当然 / 以下是」这种客套话，还是直接给东西 |
| **合规边界** | 测模型怎么处理处在合规边界上的话题。和「拒绝话术」是**相互独立**的两道门 —— 很多模型能过内容门槛却卡在边界判定上 |

输出：**生效百分比**、**评级**（完全/大部/部分/轻微/未生效）、**范围明细**，报告可导出 Markdown。

**「⚡ 一键跑全部服务商」**：把你填过密钥的每一家都跑一遍，出一张对照表 ——
一眼看出同一个模板在不同服务商上的差异，也看得出哪家是被**平台内容审核**拦的（那种改提示词没用）。

> 批量测试支持两种覆盖范围：**每家第一个模型**（快 · 省）或 **每家的全部模型**（完整）。
> 点之前会告诉你大概要发多少次请求。

### 6. 拒答自动换路（拒答回退阶梯）

被拒答时不再直接报错，而是按**代价从低到高**自动换手段重试，每一级都会如实告诉你正在做什么：

| 级别 | 手段 | 解决什么 |
|---|---|---|
| 1 | **官方避拒回退**（Claude） | 接上 Anthropic 官方的 server-side fallback，分类器拒答时由 API 自己重试到它推荐的回退模型 |
| 2 | **预填加强** | 同一模型加一条「已同意」的 assistant 预填，绕过「拒绝被触发的那一点」 |
| 3 | **代际回退**（Claude 专用） | 5.x 系自带输入侧安全分类器（拒的是正文整体模式，改措辞无用），自动退到实测可用的 4.x 代际 |
| 4 | **网关回退** | 同一个模型换一条路走（如百炼 → 硅基流动）。实测同一个通义千问，走百炼被双向审核卡死，走硅基流动 4/4 全部通过 —— 模型没变，变的是中间那条路 |

### 7. 服务商能力矩阵

27 家逐个标注档位，**每条都带实测证据；没实测过的绝不标「通过」**：

| 档位 | 含义 | 处置 |
|---|---|---|
| 可直接破 | 提示词层生效 | 直接用内置模板 |

| 未实测 | 没有实测证据 | 不下结论 |

### 10. 壁纸引擎（应用自带，参数全可调）

- **8 款内置动态壁纸** + 本机图片/视频 + 「🖼️ 扫描小红车壁纸」一键选用
- **会动的那两类都能动**：视频壁纸（`.mp4/.webm`）直接读盘播放（实测 3840×1772 的循环视频，
  静音 + 循环 + 切后台暂停）；动图（`.gif/.webp`）按图片走，同样会动
- **场景类壁纸（`scene.pkg`）取包里原画**：这类壁纸在 WE 里是实时渲染的，
  过去只能退而用 1024×1024 的工坊预览图，铺到 2560×1440 画布上等于放大 + 裁切。
  现在自动解析包里的 PKG/TEX（LZ4 块链、DXT1/3/5、内嵌 JPEG 直通），取出**作者原图**
  并裁掉图集黑边 —— 本机 91 个场景包实测 **87 个取图成功**，平均 **2863²**、最大 7680×2160；
  用户那张取到 **3840×2160（比预览图清晰 7.9 倍）**，且正好 16:9、铺满零裁切。
  解析实现来自 MIT 的 [dsh-wallpaper-engine](https://github.com/elysia395/dsh-wallpaper-engine)
  （见 `src/lib/we-scene/README.md` 的来源与许可说明），首次提取 7ms~4s，之后走磁盘缓存
- **画面基准**：固定为显示器大小 / 跟随窗口 / 固定为原图像素。
  选「固定为显示器大小」时壁纸只在开头画一次，之后**拉窗口只是露出更多或更少 —— 比例与画质都不变**
  （实测：1432×812 → 900×600 窗口变化，画面始终是 2560×1440 的画布，零重采样）；
  「跟随窗口」是旧行为（每拉一次都重新铺满）；「固定为原图像素」不放大，小图按原像素显示最清晰
- **画面缩放** 50%–200%：在基准尺寸上再乘一个倍率，想让画面显得小一点、看到更多内容就往左拉
- **填充方式**：智能 / 铺满裁切 / 完整显示（模糊补边）/ 拉伸 / 平铺。
  智能模式会按「画布比例 ÷ 图片比例」自动挑，裁得太狠就切成「完整显示 + 同一张图的模糊版补边」，
  既不裁掉半边，也不留黑边（信息行会写明「场景包原画 3840×2160（比预览图 1024×1024 清晰 7.9 倍）· …」）
- **面板实度**（0–100%）：拉到 0 = 面板完全透明，壁纸原样透出来
- **面板模糊**（0–120px）：管面板背后的虚化，0 = 壁纸细节全留（与「壁纸模糊」是两件事）
  —— 想让原画的细节看得见，把它往小拉
- **深色壁纸自动翻字**：主进程顺手算壁纸平均亮度，暗图自动切「深玻璃 + 浅字 + 深描边」，
  亮图用「白玻璃 + 深字」；弹窗、下拉、快捷指令面板、Toast 全都跟着走（不会出现白底白字）
- **窗口真透明**（可选，重启生效）：连桌面都能透出来，配合面板实度 0 就是「只剩浮在桌面上的文字」

## 🛡️ 防封中心（设置页）

**先说清楚：任何客户端都无法保证你的账号「一定不被封」** —— 封不封由服务商的服务端判定。
这个面板做的事是：把你这边**容易踩的坑**提前查出来、能自动修的自动修掉。

**Claude 与 GPT 各有一组按钮**（一键优化 + 防封体检）。检查项是通用的，
区别在于**报告会按对应厂商的政策口径出** —— 两家的规则并不一样。

### ⚡ 一键优化到底做什么

优化键不是摆设：**它会告诉你分数从多少变到多少**，而且尽量把能自动修的真的修掉。

| 动作 | 能不能自动做 |
|---|---|
| **自动探测并配置本机代理** | ✅ **能** —— 扫 10 个常见端口（7897 / 7890 / 10809 / 1080 …），挑一个出口在受支持地区的自动配上。这是**唯一一个能自动修掉 -25 分项**的动作 |
| 开启请求节流（串行 + 间隔 + 抖动） | ✅ 能 |
| 请求语言对齐出口地区 | ✅ 能 |
| 清环境变量残留 | ⚠️ 给**可一键复制的命令**（应用不去改系统环境变量，那会影响你其它软件） |
| 改系统时区 | ❌ 给操作步骤 |
| 换掉脏的出口 IP | ❌ 给判断方法 |

> 优化只在**确实需要**时才动代理：当前出口是高风险地区、或压根没测到出口，才会去探。
> 出口本来就正常的人不给你乱配 —— 那只会更糟。

### 检查项

| 检查 | 说明 |
|---|---|
| **出口网络** | 查你实际从哪个 IP / 地区 / 线路出去，读 IP 情报的托管标志，区分**住宅线路 / 机房 IP / 代理出口 / 移动网络** |
| **环境一致性** | 把「出口地区 · 系统时区 · 系统语言」放一起比对；不一致就提示，**请求语言可一键对齐出口地区** |
| **出口地区跳变** | 24 小时内换过 3 个以上地区会报红。官方风控明确会监控「IP 位置变化频率」—— 几分钟从纽约跳到伦敦，正常人的网络不会这样 |
| **请求节奏** | 同一服务商串行发送、每次至少间隔几秒，并加 0–2 秒随机抖动（机器般精确的等间隔反而像脚本） |
| **限额感知** | 读取服务端返回的额度信息，剩余不多时**自动放慢发送间隔** |
| **严格遵守服务端要求** | 被限流时按服务端告知的等待时间等，不自己拍一个退避；区分「本轮额度」与「账户额度」 |
| **失败熔断** | 连续被限流时自动暂停一段时间，不再连续重试 |
| **环境变量残留** | 检出 `ANTHROPIC_BASE_URL` 这类变量。用过镜像站 / Claude Code Router / 各种中转后常留下它，**公开防封资料明确点过：服务端一看请求就知道你没走官方**。应用给可复制的清理命令 |
| **请求身份指纹** | 检查请求头里的 User-Agent 是不是一个「所有用户完全相同、还带着软件名」的标签 |
| **中转站凭据风险** | 用中转/转发类服务时提醒：**只填中转站自己的 key，绝不要把原厂 key 填进去** |
| **厂商政策差异** | 按当前服务商列出该家的政策要点 |

### 两家规则的实质差异（写在报告里）

## 常见问题

**Q：必须买吗？**
不用。下载与绝大部分功能都免费；只有内置模板、启用模板开关、指令检测、拒答回退阶梯四项
采用一次性解锁。自己写的自定义模板可以免费用。

**Q：是订阅吗？会到期吗？**
不是订阅，是**一次性解锁**，不按月收费、不自动续费。

**Q：密钥会上传到你的服务器吗？**
不会。密钥只存本机（能用系统密钥库时自动加密），请求直接从你的机器发往模型服务商。

**Q：换电脑要重新买吗？**
激活码绑定设备。换电脑需要在应用里拿到新设备码，联系作者换发激活码。

**Q：更新会丢配置吗？**
不会。对话记录、插件、API 配置都在 `%APPDATA%\Lumen`，换 exe 不动它们。
应用内「设置 → 关于 → 数据目录」可以自己打开确认。

**Q：怎么卸载？**
删掉那个 exe 就完事了（免安装、不写注册表）。要连配置一起清，再删 `%APPDATA%\Lumen`。

**Q：支持 macOS / Linux 吗？**
目前只发布 Windows x64 版本。

**Q：请求失败怎么办？**
先看「设置 → 防封中心」的结论；再确认密钥是否有效、余额是否充足、该服务商是否需要特定的网络环境。
应用会把「模型拒答」「被平台拦截」「网络错误」分类提示，不会让你误判。

**Q：模型清单里怎么才这几个？**
内置的只是「开箱即用的常用款」。点「模型接入」页右上角的 **「⟳ 拉取全部模型」**，
或「指令检测」页模型框旁的 **「⟳ 拉取清单」**，从各家官方接口拉真实清单 —— 聚合平台通常有几百个。

**Q：为什么模型拒答？**
应用会把拒答按原因分类：**模型级拒答**（模型自己的安全对齐）／**网关审核**（中间商拦的）／
**客户端送审**（那家自己的客户端拦的）。不同类型的处置完全不同，应用会指出来。
Claude / GPT 这类"模型级拒答"可以试试「拒答回退阶梯」（自动换代际/换网关）。

### v2.0.1 · 2026-10-05（源码已改，尚未打包发版）

**🖼️ 壁纸显示不完整 + 做不到全透明 + 外观面板里的字看不见（三处一起修）**

- **方图不再被裁掉一半**：小红车的场景类壁纸（`scene.pkg`）只能退而用它的 `preview.jpg`，
  而那是 1024×1024 的**方图**；原来一律 `object-fit: cover`，在 1560×980 的窗口里
  等于只看到中间 63% 的竖条，用户看到的就是「壁纸显示不完整」。
  现在新增**填充方式**（智能 / 铺满裁切 / 完整显示（模糊补边）/ 拉伸 / 平铺），
  默认「智能」：按「窗口比例 ÷ 图片比例」算出**铺满要裁掉多少**，超过 1.35 倍就自动切成
  「完整显示 + 同一张图的模糊版补边」——不裁、不留黑边。设置页那行信息会写清楚：
  `原图 1024×1024 · 铺满要裁掉 43% · 填充：完整显示（模糊补边）`。
- **「不能做到全透明」的真因是面板玻璃写死了**：旧版把面板固定成「白 50% + blur 100px」，
  壁纸被洗成一片色块；而设置页那个「模糊」滑杆只管壁纸自己（`--wp-blur`），管不到面板，
  所以用户把模糊拉到 0 也没变化。现在拆成两个可调量并真正接到 CSS：
  **面板实度**（0–100%，0 = 面板完全透明）与**面板模糊**（0–120px，0 = 壁纸细节全留）。
- **深色壁纸自动翻字**：面板透明后文字直接压在图上。主进程用 `nativeImage` 顺手算壁纸平均亮度
  （Rec.709，24px 缩略图上取平均），低于 42 就切「深玻璃 + 浅字 + 深描边」，亮图仍是
  「白玻璃 + 深字」，所以拉到全透明也不会看不清字。
- **外观面板（右上角齿轮）补上整块样式**：它原来有 DOM 没有 CSS —— 被当成普通块级元素插进
  `<body>`，把 `.app` 挤矮、自己又落在窗口最底部，且 `z-index: auto` 被壁纸层
  （`fixed` + `z-index: 0`）整层盖住，所以「点开齿轮看不到字」。现在它是贴着齿轮的
  定位浮层（`fixed` / `z-index: 90` / 玻璃底 / 圆角 / 阴影），行与行对齐，并新增一行
  **字体预览**。
- **字体选择过去是失效的**：`dsh-theme.css` 里 `body { font-family: var(--dsw-font-family) }`
  在 `styles.css` 之后加载，把 `--font-ui` 整个盖掉 —— 下拉框怎么选都没反应。现在改成
  `var(--font-ui, …)`（`--sans` 也带上），实测切到 SimHei 后物理字体确实变成 SimHei。
- **字体列表标出「未安装」**：Inter / Noto Sans SC / PingFang SC / JetBrains Mono 这些
  本机多半没装，选了看着「没变化」。现在用 `FontFace` + `local()` 探测（canvas 量宽度分不出
  中文字体：中日韩字形都是 1em 等宽），没装的直接写成「Roboto（未安装）」并给出提示。
- 另修：壁纸关掉时背景层还挂着一层灰纱（`:empty` 兜底）、窗口可开**真透明**（可选，
  重启生效；配合面板实度 0 就是「只剩浮在桌面上的文字」）。

> 三处都做了可视化回归取证（`tools/visual-check.mjs`：CDP 驱动独立 userData 的 dev 实例
> 逐屏截图），并把这些断言写进应用自检的 `wallpaper` 一项（控件存在、变量接线、
> 面板有 z-index、参数脏值会被夹住、字体走 FontFace 探测）。

**🐛 点开就纯白、字看不清 + 拉窗口会重采样（同批修完）**

- **「很多按键点开过后是纯白、看不清字」的真因不在壁纸层，而在跨观感的 CSS 泄漏**：
  `dsh-theme.css` 里有两条规则**没带 `[data-ui]` 前缀**——
  `:root[data-theme="light"] .modal { background: var(--dsw-static-neutral-bluish-00) }`（纯白）
  与 `:root[data-theme="light"] { --panel / --bg-soft / --ui-code-bg / --dsw-bg-layer-* … }`。
  后者的特异性 (0,2,0)/(0,3,0) 比主题层还高，于是：浅色主题下弹窗、下拉、代码块、chip 选中态
  会被刷成不透明白/浅灰的底，而壁纸模式按「深壁纸 → 浅色文字」走 —— 白底白字，什么都看不见。
  修法：壁纸模式的选择器统一加 `[data-theme]` 提权到 (0,3,1)/(0,4,1) 压过它们，
  并在同一处接管 `--bg-soft / --ui-code-bg / --ui-hover / --ui-active / --dsw-bg-layer-* / --dsw-label-*`
  这些被泄漏的 token，显式把 `.modal / .cmdk / .toast / .attachments / .dropdown` 与弹窗里的
  输入框、代码块纳入玻璃层。**顺带修掉一个隐患**：暗色主题下 `--bg` 曾被主题纯色 token 盖成
  `#202020`，等于开了壁纸也看不见（现在暗色一样透）。
- **「拉窗口会影响壁纸比例/画质」→ 新增「画面基准」+「画面缩放」**：
  旧行为是画面永远铺满窗口，每拉一次窗口就重新采样一次（画面跟着缩放、小图越拉越糊）。
  现在可把画面基准设成**固定为显示器大小**（画布只画一次，窗口只是它的一扇窗）、
  **跟随窗口**（旧行为）或**固定为原图像素**（不放大，最清晰），再乘一个 50%–200% 的画面缩放。
  实测判据写进 `tools/visual-check.mjs`：1432×812 → 900×600 视口变化时，
  固定画布的画面尺寸恒为 2560×1440（零重采样），跟随窗口的才会跟着变。
- 新增 `tools/contrast-audit.mjs`（WCAG 对比度审计）与 `看效果-免打包.cmd`

（`/scene-files/…`、`/media/…`，支持 Range）而不是 base64 —— 这两点（**用原图 / 不重编码**）
正是「不降画质」的来源。它还提供亮度/对比度/饱和度/透明度/暗化/翻转、帧率上限（ffmpeg 抽帧转码，4K 保留）

本次按这个思路补进 Lumen 的（不做完整场景引擎移植）：

- **场景包取原画**：新增 `src/lib/we-scene/`（解析代码 MIT 搬自上述插件，来源与许可写在目录 README 里）
  + 主进程 `wallpaper:sceneFrame`（读 pkg → 取主纹理 → 裁黑边 → PNG 落盘缓存）+ 渲染层自动采用。
  效果：用户那张场景壁纸从 **1024×1024 预览图** 换成 **3840×2160 作者原图**（清晰 7.9 倍、零裁切），

- **会动的两类明确化**：视频壁纸实测 3840×1772 循环播放（`paused:false`、时间轴前进、切后台暂停）；
  动图（gif/webp）走图片路径同样会动；扫描结果里给「视频 / 场景 / 动图预览」分别打标。
- **画质对照取证**：`screenshots/lumen-scene-art-vs-preview.png`（左＝原画、右＝预览图，同区域放大），

- 现在递归展开：里面的文件一个个带进来（是文本的读正文、是图片的给预览）
- **上限是刻意设的**：最多 200 个文件、最多 5 层深，并自动跳过 `node_modules` / `.git` / `dist` /
  `__pycache__` 这类依赖与构建目录 —— 不然拖一个项目文件夹进来会瞬间把上下文和钱包都烧掉。
  触到上限会明确告诉你「还有没带上的」，**不偷偷截断**

**📁 文件夹只占一行，可展开收起**

- 文件多的文件夹不再把附件条铺满：显示成**一条**（📁 名字 + 「N 个文件 · 总大小」），
  旁边有「展开 ▸ / 收起 ▾」，想看里面有什么再点开，默认收起
- 展开后子文件带缩进；也能单独摘掉里面某一个
- 发出去的是**里面那些文件**，不是那个文件夹的空壳

**✂️ 截图：框选 + 标注 + 调大小**

- 点截图按钮不再整个屏幕糊一张，而是弹出框选界面：**拖一个框，只截那一块**（松手即截）
- 框选时实时显示「这块有多大」（宽 × 高像素）
- **单击 = 截整屏**；**Shift + 点击截图按钮 = 直接抓整屏**；Esc 取消
- **框完还能直接画**，三种标注工具：**▭ 矩形框** / **↗ 箭头** / **▦ 马赛克**（盖住手机号、
  密钥这类敏感信息），支持一笔一笔撤销。标注完点「✓ 完成」，保存并附加的是带标注的成品
- 支持按「最大宽度」等比缩小 —— 大屏截图发给模型又贵又糊，缩一下省不少 token
- 用户取消时**不会在截图目录留下没用的整屏图**（预览图只在内存里）

**🔧 自动更新修复（这次是真因）**
- **弹窗的根因找到了**：Node 的 `detached: true` 会**主动给子进程建一个控制台窗口**
  （官方文档原话 "The child will have its own console window"），
  而 `windowsHide: true` 管不了它 —— 这就是用户看到的黑框。改用 `CREATE_NO_WINDOW`
- **不再死等 PID**：旧脚本用 `tasklist | find "<pid>"` 死等应用退出，应用只要没退干净
  （托盘 / 窗口被重建 / PID 被复用）就**永远转下去**。改成「重试覆盖文件直到成功」+ 硬超时 + 回滚
- 退出链路加了**看门狗**：`quit()` 走不完就 5 秒后强制退出，不留半死不活的进程
- 更新包下载后清掉「来自互联网」标记，**不会再弹 SmartScreen**「Windows 已保护你的电脑」
